# かわばた日和（KAWABATA BIYORI）

秋田市・川反（かわばた）の地域Webマガジン。運営：Café & Bar Sereness

> 今日もちょっと、川反へ。
> いつもの川反も、はじめての川反も。知れば知るほど、好きになる。

Next.js 16（App Router）・TypeScript・Tailwind CSS v4・Supabase で作っています。公開サイトと管理画面（CMS）は同じプロジェクトにあります。

## 1. 川反の分析（サイト設計の前提）

### わかっていること

出典は記事末尾にも記載しています。公開前に原文で確認してください。

| 項目 | 内容 | 出典 |
|---|---|---|
| 場所 | 秋田市**大町**の**旭川沿い**。「川反」は通称で、現在の住所表記は大町 | JR東日本秋田支社コラム、観光サイト |
| 通り | **川反通り**（旭川沿い）、五丁目橋を渡った先の**横町通り**、**赤れんが館通り**が中心 | JR東日本秋田支社コラム |
| アクセス | 秋田駅西口から徒歩20分ほど。バスなら「川反入口」が近い | JR東日本秋田支社コラム、ホテル案内 |
| 名前の由来（説） | 藩政時代は「川端」。旭川の東が武家町、西が町人町だったため、武士から見て「川の反対側」として「川反」の字が当てられた、という説 | 観光サイト・郷土紹介 |
| 歓楽街の始まり | **明治19年（1886年）の大火**（俵屋火事）で焼けた芸者屋・料理店が移ってきたのが始まりと言われる | JR東日本秋田支社コラム |
| 最盛期 | 明治末〜昭和初期。郷土史家・田口松圃は大正初め〜大正12年ごろを全盛期とする | JR東日本・秋田魁新報 |
| 芸者衆 | 芸者置屋は明治43年13軒 → 大正8年35軒。芸者97人・舞妓47人（大正8年の秋田魁新報） | 秋田魁新報（2021年11月21日） |
| 今に続く文化 | 「あきた舞妓」が川反芸者の文化を受け継ぐ。拠点は千秋公園内の「あきた文化産業施設 松下」（旧割烹松下） | ANA Japan Travel Planner |

**わからなかったこと**：店舗数、来街者数、年齢層などの統計は、今回の調査では見つかりませんでした。秋田市の統計や商店街組合に確認すると、記事や営業資料に使えます。

### 設計への反映

- **「入りにくさ」を減らすのが最優先**：料金がわからない、常連ばかりで入りにくい、という初心者の不安に向けて、「はじめての川反」ガイド（5ステップ）と「**初心者歓迎マーク**」（料金明確・初来店歓迎・料金説明あり・不明瞭な追加料金なし）を中心に置きました。
- **新しい層の入口をつくる**：一人飲み・ノンアル・女性グループ向けに、店舗検索の「一人利用OK」「ノンアル対応」の絞り込みと、初期記事を用意しました。
- **歴史を「物語」として使う**：花街の歴史、あきた舞妓へのつながりは、川反だけの強みです。「川反の歴史」カテゴリーで発信します。
- **暗すぎない夜の街**：アイボリー×ダスティピンク×ネイビーの配色で、夜の街を扱いながらも明るく清潔な印象にしています。
- **川反全体のメディアにする**：運営店だけに偏らないよう、店舗紹介は川反全体を対象にし、広告記事には「PR」を表示します。

## 3. セットアップ

### 3-1. 手元で動かす（デモモード）

Supabase を設定しなくても、デモデータで画面を確認できます。

```bash
cd kawabata-biyori
```

```bash
npm install
```

```bash
npm run dev
```

http://localhost:3000 が公開サイト、http://localhost:3000/admin が管理画面（デモモード：保存できません）です。

デモモードで表示されるのは次のデータです。

- **初期記事10本**：すべて「公開前の下書き」として表示します。
- **架空のサンプル店舗3件とイベント1件**：「架空のサンプル」と表示し、検索エンジンにはインデックスさせません。

### 3-2. Supabase を接続する

1. [Supabase](https://supabase.com) でプロジェクトを作ります。
2. SQL Editor で `supabase/migrations/0001_init.sql` を実行します。テーブル、RLS、画像用の Storage バケット、初期カテゴリーが作られます。
3. 続けて `supabase/seed.sql` を実行します。初期記事10本が**下書き**で入ります。
4. Authentication → Users で管理者のユーザーを作り、SQL Editor で管理者として登録します。

   ```sql
   insert into public.admin_profiles (user_id, display_name)
   select id, '編集部' from auth.users where email = 'あなたのメールアドレス';
   ```

5. `.env.example` を `.env.local` にコピーして、Supabase の URL と anon key を入れます。

### 3-3. 環境変数

| 変数 | 用途 | 必須 |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | 公開URL（canonical・OGP・サイトマップ） | 本番では必須 |
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | データベース・認証・画像保存 | 本番では必須 |
| `ANTHROPIC_API_KEY` | AI文章生成（Claude） | AI機能を使う場合 |
| `OPENAI_API_KEY` | AI画像生成・編集 | 画像生成を使う場合 |

- APIキーはサーバー側だけで使い、ブラウザには送りません。
- コードやリポジトリにキーを書かないでください。
- AIのモデル名・考える深さ・1日の利用上限は、管理画面の「AI設定」で変えられます。

### 3-4. Vercel で公開する

1. Vercel でこのリポジトリを読み込み、**Root Directory を `kawabata-biyori`** にします。
2. 上の環境変数を設定してデプロイします。

AIの生成は1〜2分かかることがあるため、APIは最大300秒まで動くように設定しています（Vercel のプランによって上限は異なります）。

## 4. 運営のルール（仕様書 第24章をコードに反映）

- **AIの記事は自動公開しない**：生成した記事は必ず「下書き」で保存します。本文の先頭には「公開前の事実確認メモ」が入るので、確認が済んだら削除してください。
- **実在しない店舗・人物を作らない**：AIへの指示で禁止しています。具体的な店名・料金は「参考情報」に書いたものだけを使い、ない場合は【要確認】と書かせます。
- **AI画像の扱い**：公開ページでは「イメージ画像」と表示し、実在するお店の写真としては扱いません。
- **店舗の公開条件**：店舗を公開するには「情報の最終確認日」が必須です。写真を使う場合は「写真使用の許可」の確認も必須です。
- **初心者歓迎マーク**：掲載基準の4項目をすべて確認しないと付けられないようにしています。
- **広告の明示**：広告・タイアップ記事にチェックを入れると「PR」を表示します。

## 6. フォルダ構成

```
kawabata-biyori/
├─ supabase/
│  ├─ migrations/0001_init.sql   テーブル・RLS・Storage・初期カテゴリー
│  └─ seed.sql                   初期記事10本（下書き）※ npm run seed:export で生成
├─ scripts/export-seed.ts        初期記事 → seed.sql
└─ src/
   ├─ app/(site)/                公開サイト
   ├─ app/admin/(panel)/         管理画面
   ├─ app/admin/_actions/        保存処理（Server Actions）
   ├─ app/api/admin/ai/          AI API（構成・本文・SEO・リライト・画像）
   ├─ components/site/           公開サイトの部品
   ├─ components/admin/          管理画面の部品（TipTapエディターなど）
   ├─ lib/data/                  公開データの取得（デモ／本番の切り替え）
   ├─ lib/ai/                    AI呼び出し・利用制限・履歴
   ├─ lib/demo/                  デモデータ・初期記事
   └─ proxy.ts                   管理画面のログイン確認
```
